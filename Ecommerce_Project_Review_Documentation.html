1. Executive Summary & Project Overview

NexCart is a state-of-the-art Single Page Application (SPA) designed to deliver a modern, fluid E-commerce shopping experience while implementing academic and industry-grade Database Management System (DBMS) concepts. The platform simulates a relational database architecture on the client side, allowing complex multi-table queries, aggregation calculations, and data integrity enforcement.

Core Tech Stack Breakdown

Technology Layer Component Specification Implementation Purpose
Front-End UI HTML5, Vanilla CSS, JS (ES6) Modular components, fluid animations, premium Glassmorphic elements.
SPA Routing Engine HTML5 History API (pushState/popstate) Seamless view transitions, browser back-button & mobile swipe gesture support.
Relational Database Engine Local Simulation Layer (localStorage) Underpins 4 related tables representing relational schemas and attributes.
Dynamic Analytics Chart.js via CDN Donut and bar charts representing product reviews and monthly sales ratios.
PDF Document Exporter jsPDF Library via CDN Compiles real-time order invoices into native binary PDF files in new tabs.

System Objectives

  • Academic Rigor: Verify multi-table data joins and aggregate queries.
  • Referential Integrity: Implement DBMS-level Foreign Key verification and ON DELETE RESTRICT constraint logic.
  • User Experience: Responsive design covering smartphones (dynamic viewport heights) up to widescreen desktop layouts.

Database Entity Relationship Schema Summary

The tables are mapped using strict Key constraints inside model.js:

  • Users: Email is the unique Primary Key (PK).
  • Categories: category_id (PK) links to Products category field (FK).
  • Products: product_id (PK) links to Order_Items product_id field (FK).
  • Orders: order_id (PK) links to Order_Items order_id field (FK) and contains user_email (FK).

4. Technical Implementation & Database Details

Database Tables Schema

1. Categories Table: { id: STRING (PK), name: STRING, icon: STRING }
2. Products Table: { id: STRING (PK), name: STRING, category: STRING (FK), price: NUMBER, mrp: NUMBER, stock: NUMBER, image: STRING, description: STRING }
3. Orders Table: { id: STRING (PK), user_email: STRING (FK), date: STRING, total_amount: NUMBER, promo_code: STRING, discount: NUMBER, status: STRING }
4. Order Items Table: { id: STRING (PK), order_id: STRING (FK), product_id: STRING (FK), quantity: NUMBER, price_per_unit: NUMBER }
